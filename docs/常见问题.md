# 常见问题

## 安装与启动

### 提示「Windows 已保护你的电脑」/ 未知发布者，是病毒吗？

不是。安装包使用项目自签名证书（`CN=Danmu API`），没有购买商业代码签名证书，所以 SmartScreen 会提示"未知发布者"。
确认下载来源是本仓库的 Releases 后，点 **更多信息** → **仍要运行** 即可。

想更稳妥可以先核对 SHA256 与签名，见 [安装与使用](安装与使用.md) 和 README 的「校验下载文件」。

### 首次启动卡在「正在准备运行环境」

这一步要把内置的 Node 与生产依赖铺到本机（约 160 MB、6000 多个文件），所以会受这些因素影响：

- 磁盘慢或空间不足；
- 杀毒软件 / 安全软件的实时扫描（可以把 `%LOCALAPPDATA%\DanmuApi` 加入信任目录，会明显变快）；
- 系统盘剩余空间。

准备只需要一次，之后启动是几十毫秒的快速校验。如果中途失败，页面上会有明确的失败原因与修复入口。

### 启动服务后局域网设备连不上

按顺序排查：

1. **监听地址**：配置里的 `DANMU_API_HOST` 要是 `0.0.0.0`；如果被设成 `127.0.0.1` 就只能本机访问。
2. **防火墙**：第一次启动服务时应该弹过授权窗口。若当时拒绝了，可在「设置」里重新申请，
   或到「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」手动放行 `node.exe`。
3. **地址写法**：要用本机在局域网里的 IP（例如 `http://192.168.1.20:9321/<TOKEN>`），不要用 `127.0.0.1`。
4. **网络类型**：Windows 把当前网络识别为"公用网络"时限制更严，可在系统设置里改成"专用网络"。

概览页会直接列出可用的接口地址，照着填即可。

### 提示端口被占用

- 如果是**本应用自己的另一个实例**（比如窗口和托盘各开了一份），提示会说明"已在其他窗口/托盘运行"，
  到那个实例里停止服务即可。
- 如果是**其它程序**占用了端口：换一个端口（配置里的 `DANMU_API_PORT`），
  或者找出占用者自行处理。应用只做只读探测，**不会替你结束别人的进程**。

### 关闭窗口后应用不见了

看「设置 → 关闭窗口时」的选项：可能是设成了「最小化到托盘」。到任务栏右下角托盘图标里找回来即可。

## 核心与依赖

### 「核心依赖」显示缺失怎么办？

先看缺的是什么：

- 如果显示 **正常**，忽略即可。
- 如果显示 **缺失 N 项**：说明当前核心在自己的依赖清单里声明了随包运行环境没有的包。
  应用会在核心安装/更新完成后自动核对一次并弹窗提示，其中列出的就是缺的具体包名。

本应用随包提供宿主自己需要的依赖，**不提供**核心在 Windows 下不会用到的那几个包
（例如核心只在命令行入口里用到的文件监听、`.env` 解析、构建工具等）。
如果列表里是这些名字，通常不影响服务运行，可以直接启动试试；若服务确实起不来，
换用稳定核心版本，或联系核心发布方。

### 「可选 Redis」是什么？要配吗？

不用管。核心只有在配置里设置了 `LOCAL_REDIS_URL` 时才会用到 Redis。
一旦你填了它、应用就会把随包的 Redis 依赖铺到运行环境里，「运行状态」里会出现「可选 Redis 已启用」。
没填就不会显示这一项，也不会占用空间。

> 注意：先启动过应用、之后才填 `LOCAL_REDIS_URL`，需要重启一次应用才会铺开。

### 核心更新后服务起不来

1. 到「核心」页看服务状态与失败原因——应用会把核心日志的尾部直接显示出来；
2. 用「本地版本历史」回退到上一个可用版本（不需要重新下载）；
3. 若仍不行，到「活动 / 日志」页查看完整日志后再反馈。

### 自定义核心 / PR 版本能日常用吗？

它们的来源不受稳定版校验，属于尝鲜用途。出问题随时用「核心」页的「本地版本历史」回退。

## 更新

### 「检查更新」和「应用更新」是什么的更新？

「核心」页更新的是**弹幕核心**（Node 那边的程序）；
「关于」页更新的是**本应用**（这个 Windows 客户端）。两者互不影响。

### 检查到新版本后必须马上更新吗？

不用。检查到新版本时会问你是否立即更新；选"稍后"后按钮会留在页面上，随时可以再点。
更新完成前设置的跳过版本只影响自动提示，手动检查仍能看到。

### 为什么更新完还提示有新版本？（旧版本的问题）

0.3.2 及更早版本有这个问题，0.3.3 已修复。升级到 0.3.3 后不会再出现。

### 应用更新会动我的核心和配置吗？

不会。更新只替换程序文件，核心、配置、日志和下载内容都在用户数据目录里，保持原样。

## 数据与隐私

### 我的 Token / Cookie 存在哪？安全吗？

- 变量值保存在核心的 `config\.env`（`%LOCALAPPDATA%\DanmuApi\runtime\nodejs-project\config\.env`），
  和核心自己维护的配置文件是同一份。
- GitHub Token、管理员密码这类**应用侧**凭据保存在 `%APPDATA%\DanmuApi\*.dat`，
  用 Windows DPAPI 加密，只有当前 Windows 用户能解密。
- 界面上敏感变量默认打码显示；应用日志从不记录这类明文值。

### 卸载会删掉我的数据吗？

不会。卸载后 `%LOCALAPPDATA%\DanmuApi` 与 `%APPDATA%\DanmuApi` 都保留，重装即接着用。
彻底清理请手动删除这两个目录，或先到「设置 → 数据与备份」导出备份。

### 数据能在另一台电脑上用吗？

可以。「设置 → 数据与备份」支持导出 / 导入备份，也支持 WebDAV 远端同步。
备份包含核心配置与相关数据，但不包含内置的 Node 与依赖（那些目标机器会自己准备）。

### 应用会上传我的数据吗？

不会。应用只做这几类网络请求：访问 GitHub 获取核心与软件更新、按你的配置访问弹幕数据源、
以及你主动配置的 WebDAV 备份地址。没有遥测上报。

## 其它

### 支持 32 位系统 / ARM 吗？

暂不支持。当前只提供 Windows x64 版本：Node.js 官方自 v19 起不再提供 win-x86 二进制，
ARM64 版本尚未提供。

### 支持便携（免安装）使用吗？

支持。免安装版解压即用，程序文件不写注册表（除开机自启外不产生系统改动），
数据仍然放在用户数据目录，也可以把整个数据目录一起拷走。

### 有没有命令行参数？

有少量维护用参数，普通使用不需要：

| 参数 | 用途 |
|---|---|
| `--release-self-test <报告路径>` | 自检运行环境与通知，不启动核心 |
| `--verify-app-release <发行目录>` | 校验一个发行目录里的清单签名与资产 |

### 界面语言能换吗？

目前只有简体中文界面。
