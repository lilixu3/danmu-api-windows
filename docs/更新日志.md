# 更新日志

## v0.5.7 — 三架构发布（64 位 / 32 位 / ARM64）+ 修复"删核心后重装卡住"

### 新增

- **同时支持 64 位、32 位与 ARM64 三个架构**：每个架构都有安装包与免安装包，三者的界面与功能完全一致
  （内置同一套 Node.js 运行时 22.23.2，只是按架构取对应的官方二进制）。
  - **64 位**：Windows 10/11 x64；在 ARM64 的 Windows 11 上也用这一套（走系统兼容模式）。
  - **32 位**：仅用于 32 位 Windows（在 64 位系统上装不上，请用 64 位包）。
  - **ARM64**：ARM64 版 Windows 11 的原生包。
- **应用内更新只下载当前架构的包**：更新时会按你的程序架构选择对应的签名清单并校验清单里的架构字段，
  因此不会拿到别的架构的包；已装 64 位版就继续更新 64 位，ARM64 原生版就更新 ARM64。

### 修复

- **删除核心后再装回核心，服务不再卡住**。删除当前核心时应用会有意停止服务并让运行时进入
  "等待准备核心"（避免服务带着缺失的核心运行）。但在这个状态下"启动服务"按钮与托盘的同名菜单项
  都是灰的，而装回核心后又没有重新评估这个状态——结果就是核心页显示就绪、依赖也正常，
  服务却一直停在"等待准备核心"，怎么点都没反应，只能重启应用。
  现在：该状态下两处启动入口都可用（核心已装好就正常启动；核心仍缺失则照旧弹出去核心页安装的确认），
  并且核心安装/回滚成功后会重新评估该状态——核心就绪时运行时回到"已停止"，直接就能启动服务。
- **删除核心的确认按钮改为"停止服务并删除核心"**：把"会停服务"这个后果放到你实际点击的位置
  （正文原本已写明，现在更醒目）。

### 说明

- 该卡住缺陷在更早版本就存在，与内置 Node 运行时无关；触发路径是"**服务运行中删除核心 → 再装回核心**"。
- ARM64 包**尚未在 ARM64 实机上验收**（构建机是 x64，无法执行 ARM64 程序）；已用验签、PE 架构与
  SHA256 逐项核对产物，实机验证随后进行。

## v0.5.6 — 内置运行环境统一到 Node.js 22.23.2

本版把随包的内置 Node.js 运行时统一到 **22.23.2**，为后续用同一套运行时覆盖
64 位 / 32 位 / ARM64 三个架构做准备。

- **内置 Node 改为取自官方发布**：安装包里的 `node.exe` 现在按官方归档下载，用官方
  SHA256 清单校验归档与其中的可执行文件，并核对 PE 架构与 `node --version`；
  不再从历史归档包里提取。
- **启动前先核对运行环境**：随包记录现在写明内置 Node 的版本与架构，启动时会与本进程
  架构、与本程序要求的版本逐项比对，不一致直接给出明确原因；首次启动新版本时会重新
  核对并替换 `node.exe`（这一次启动会稍慢）。
- **依赖检查多了 Node 版本下限校验**：核心或它依赖的包所声明的 `engines.node` 要求如果
  高于内置 Node，会在依赖检查里作为明确问题报出（带具体范围与当前版本），
  不会再等到启动失败才发现。
- **用户数据与配置不做任何迁移**：Node 的编译缓存本身按"版本-架构"分目录存放，
  升级前后的缓存互不干扰。

## v0.5.5 — 变量顺序与分类顺序对齐核心前端

以前配置页里每个分类下的变量是**按变量名字母序**排的，而核心自带前端是按它自己的读取顺序排的，
习惯核心客户端的用户换过来就得重新找位置。本版把顺序对齐：

- **每个分类内的变量顺序**改为核心 `envs.js` 里 `Envs.load()` 读取变量的顺序
  （也就是核心配置页实际使用的顺序）。实测它与 `envVarConfig` 的声明顺序在 6 个分类里有
  4 个不同，所以是照读取顺序解析出来的，不是照声明顺序、更不是字母序。
- **左侧分类顺序**对齐核心前端的分类常量：API 配置 → 数据源配置 → 匹配配置 → 弹幕配置 →
  缓存配置 → 系统配置。
- 搜索结果的分组顺序与组内顺序同样跟随上述规则。
- 派生顺序只依赖核心 `envs.js` 本身（不硬编码变量清单）；万一核心将来改了写法导致解析不到，
  会平稳退回声明顺序，不会报错挡住配置页。

## v0.5.4 — 编辑弹窗定位/缩放修复 + 排序只留拖动

### 修复

- **弹窗不再跑到屏幕左上角**：宽度以前是在显示之后才改的，而 `CenterOwner` 是按显示那一刻的
  尺寸定位的，显示后再改宽度就会让窗口偏离中心。现在宽度在显示前就定下来，居中位置正确。
- **手动拉伸弹窗高度，内容会跟着变**：以前窗口用 `SizeToContent=Height`，用户一拉伸就被弹回，
  中间内容区还固定在原高度，于是出现"内容割裂、上下留白"。现在初始高度仍按内容自动量准，
  量完立刻切成可自由缩放模式，中间是弹性行会跟着长。
- **不再人为限制弹窗默认高度**：去掉之前那个高度上限，弹窗高度由内容决定，
  只有"别超出屏幕"这一层安全网；内容超出时由中间区域滚动，头尾（含保存/取消）始终可见。

### 调整

- **多选变量去掉「上移 / 下移」按钮**：有了拖动排序，两个按钮是多余的。
  键盘仍可操作——聚焦条目后按 **Ctrl + 左右方向键** 移动。

## v0.5.3 — 编辑弹窗高度/宽度优化 + 合并模式门禁 + 拖动修复

### 修复

- **多选变量的拖动排序以前是无效的**（拖着不动）。原因是拖动开始时指针没有被按下元素捕获，
  移动/松手事件收不到。现在由被按下的胶囊捕获指针，按下 → 移动 → 松手能真正改变顺序。
- **`MERGE_SOURCE_PAIRS` 不再允许单源写入**：这个变量只接受合并来源，以前关闭「合并模式」
  仍能把来源点进暂存区、点「✓」却写成单条来源。现在关闭合并模式会**禁止写入**——
  候选来源置灰并提示「该变量只支持合并来源：请先开启合并模式⋯」，而不是悄悄退化成单源。
  门禁同时挡在写入接口上，不只靠界面置灰。
- **`PLATFORM_ORDER` 默认不再开启合并模式**：它同时支持单平台与合并平台，默认点候选就是
  添加单个平台；需要合并平台时用户自己勾选「合并模式」。

### 编辑弹窗

- **保存 / 取消 固定显示在弹窗底部**：以前整个弹窗（含底部按钮）一起滚动，内容一长就必须
  拉到底部才能点保存；现在头部与底部固定不动，**只有中间内容区滚动**。
- **高度不再失控**：内容区高度按当前屏幕工作区计算并设上限，长内容只在中间滚动，
  弹窗不会顶到屏幕上下边缘；短内容仍然自适应变矮。
- **宽度跟随宿主窗口**：以前固定 560px，在宽窗口里显得又窄又长；现在按宿主窗口宽度自适应
  （夹在 520–1080 之间）。
- 只读信息框（变量类别 / 变量名 / 值类型 / 描述）的内边距与字段间距略微收紧，减少纵向占用。

### 配置页搜索

- 搜索结果**按分类分组**显示，每组带「分类名 · N 项」标题，一眼看出变量属于哪个分类
  （与核心自带前端一致）。
- **分类名也参与匹配**：输入「API」「匹配」「缓存」这类分类名，会列出该分类下的全部变量。
- 搜索提示同步说明命中了几组、共几个变量。

## v0.5.2 — 配置编辑器界面按核心前端重排

本版把配置页的**变量编辑弹窗整体重做**，排版与交互对齐核心自带前端（`/admin` 那套界面），
颜色与图标仍沿用本应用自己的风格。所有变量的编辑界面都换了新外壳。

### 弹窗结构

- 顶部固定三段只读信息：**变量类别 / 变量名 / 值类型**（现在是红色标题「编辑配置项」+ 右上角圆形关闭按钮）。
- **描述移到底部**（以前在最上面，占掉了大半个弹窗）。
- 底部两个**等宽按钮**：保存（左）｜取消（右）。

### 按变量类型各自的排布

- **合并映射表 / 弹幕偏移**：顶部「变量值」多行框就是最终保存的内容；下面紧跟一行
  **「添加规则」+「查看最近数据」**（以前"查看最近数据"在整个编辑器最底部，很容易被忽略）。
  展开「添加规则」是一个子表单：副源实体｜关系｜主源实体三列、集数路由，
  以及**来源快捷标签**——点一下会按核心规则追加到当前聚焦的输入框（没有 `@` 就追加 `@xxx`，
  已有 `@` 就追加 `&xxx`），底部「取消 / 确认添加」把拼好的规则追加进变量值。
- **映射表**（剧名映射 / 自动匹配映射）：改成核心那套——批量多行框 + 「解析并更新列表」
  + 逐行 `原始值 -> 映射值 [删除]`，底部「添加映射项」与「查看最近数据」同一行。
- **布尔变量**：改成开关（48×26 胶囊 + 启用/禁用 文案），不再是 true/false 下拉框。
- **数字变量**：改成滚轮——大号数字 + ▲/▼ 按钮 + 下方滑块，不再是纯输入框。
- **单选变量**：改成标签胶囊点选，不再是下拉框。
- **多选变量**（源排序 / 平台排序 / 源合并）：`已选择` 虚线容器（实心胶囊 + 圆形 ×）
  + 合并模式暂存区（点「✓」合成一组）+ `可选项 (点击添加)`；**已选项支持拖动调整顺序**。
- **通用文本**：按内容长度自动决定单行框还是等宽多行框。

### 说明

- 「查看最近数据」面板本身没变，仍是每页 5 条、可展开映射详情、CUSTOM_MERGE_RULES 与
  DANMU_OFFSET 提供「设为副 / 设为主 / 填入」，其余变量仅作参照。
- 配置里写坏的值仍然**保存时校验并明确报错**，不会静默落盘；已有配置也不允许被保存成空值。
- `VOD_SERVERS` 与 `IP_BLACKLIST` 保持本应用原有的结构化编辑器（未跟随核心改成纯文本框）。

## v0.5.1 — 合并类配置写入修复 + 查看最近数据 / 一键写入 / 查看详情

本版两部分：修好**合并类变量"选了却写不进去"**，并把核心自带前端的
**查看最近数据 / 一键写入 / 查看映射详情**整套能力搬进配置页。

### 修复：合并类变量能选、却写不进去

- **`PLATFORM_ORDER` 新增合并模式**：以前点候选平台只会变成并列的独立项，想配"合并平台"
  只能自己手敲 `bilibili&dandan` 到一个小输入框里，而那个框跟你选的没有关系。
  现在与核心一致：开启合并模式后点候选进暂存区，点「确认组合（合成一项）」才成为一条已选。
- **`CUSTOM_MERGE_RULES` / `DANMU_OFFSET` 底部常驻"将要保存的值"**：以前界面上看不到
  即将写入的内容。现在实时回显；内容不完整时直接说明缺哪个字段，不用等到点保存才报错。
- **"选了来源但没填剧名"不再被当空行丢掉**：这类行现在参与校验并明确提示缺什么，
  而不是被静默跳过——那正是"选了却写不进去"的另一半。
- **核心未声明的条目不再被静默丢弃**：编辑器保留并标 ⚠，保存时明确拒绝，
  不会再出现"打开编辑器再保存就改写了我的配置"。
- **不允许把已有配置保存为空值**：要恢复核心默认仍走配置列表行的「清除」。

### 新增：查看最近数据 / 一键写入 / 查看详情

配置页里 **8 个变量**现在都有「查看最近数据」，与核心前端一致：
`MERGE_SOURCE_PAIRS`、`TITLE_MAPPING_TABLE`、`AUTO_MATCH_MAPPING_TABLE`、
`ANIME_TITLE_FILTER`、`EPISODE_TITLE_FILTER`、`TITLE_NOISE_FILTER`、
`DANMU_OFFSET`、`CUSTOM_MERGE_RULES`。

- 数据来自核心的最近缓存，每页 5 条可「加载更多」，带封面、剧名、`[来源] (N集)`。
- **查看详情**：可展开「N 个剧集」与「N 个被合并源」；被合并源还能展开**映射详情**，
  逐条对比主源/副源集数并标注「匹配 / 落单」，副源的源 ID 会还原成可读的集数标题。
- **一键写入**（范围与核心一致，只出现在两个变量上）：
  `CUSTOM_MERGE_RULES` 的「设为副 / 设为主」把 `剧名@来源` 填进规则表单；
  `DANMU_OFFSET` 的「填入」把清洗后的剧名与来源填进偏移规则。
  两者都只填表单，确认后再点保存，不会绕过你直接改配置。
- 写正则的变量（三个标题过滤、两个映射表）可以用它对照缓存里的真实剧名来写规则。

### 说明

- 最近数据需要**核心正在运行**且处于管理员模式；未运行时面板会直接说明原因。
- 编辑器排版一并收紧：合并规则改成副源 / 关系 / 主源三列并排、候选来源默认折叠，
  单条规则占的高度降到约三分之一，两条规则现在一屏能看完。

## v0.5.0 — 本地弹幕支持编辑 + 开机自启 / 启动失败修复

本版汇总四部分改动（`0.4.5`–`0.4.11` 是未发布的内部测试包，本版是这批改动的正式发行版）：
新增**本地弹幕编辑**（跟进核心 1.21.1），修复**开机自启后服务起不来**，修复 **`.env` 被写坏后应用打不开**，
屏蔽词**改为整段文本编辑**（不再拆成一条一条）。
`.env` 的读写规则现已与移动端 `DotEnvCodec` 完全一致：从配置页输入的正则/路径在文件里与输入逐字相同，
旧版本写出的双反斜杠值再保存一次即自动恢复成单反斜杠。

### 新增：编辑本地弹幕

- **单集编辑**：列表每一集的「编辑」按钮（详情弹窗里也有）可以改**集数**与**文件名**。
  适合「上传时文件名识别错了」「集数填错了一位」这类情况，**不需要重新上传文件**，弹幕正文原样保留。
- **整组编辑**：每个资源组的「编辑信息」按钮可以改**标题 / 年份 / 类型 / 季**，
  组内所有文件一起改名（各文件自己的集数与文件名保持不变）。适合「剧名识别带了多余后缀」这类情况。
- **改动即时生效**：核心会按新的标题/集数重建资源键并清掉相关缓存，桌面端保存后自动刷新列表。
- **冲突会拦下**：如果改完的名字与已存在的资源撞车，核心返回 409，界面会原样提示「目标资源已存在，无法覆盖」，
  弹窗不关，可以直接改完再存。
- **权限与上传/删除一致**：编辑同样需要管理员模式（核心侧 `LOCAL_DANMU_NOT_REQUIRE_ADMIN=true` 时放开）。
  只读模式下按钮不显示，提示会说明怎么开启。

### 说明

- 编辑需要**核心 1.21.1 及以上**。核心版本更旧时不会误报成「资源不存在」，
  而是明确提示先到「核心」页更新核心。
- 界面的字段校验文案与核心逐字对齐（例如「电视剧集数不能为空」），本地校验与核心返回的报错不会出现两套说法。

### 改动：屏蔽词改为整段文本编辑（不再拆成一条一条）

- **之前的问题**：屏蔽词编辑器把值拆成「一条一行」的列表，而正则里的 `{2,4}`、`[a,b]` 都带逗号，
  于是出现两种毛病——早期版本直接把一条正则切成 `/.{20`、`}/` 这种碎片；
  改成按核心规则分词后不再切碎，但界面仍然把一整段文本呈现成 N 个独立条目，
  既看不出原文（逗号、间距、顺序），保存时还会重新 trim/拼接一遍。
- **现在的做法**（与移动端 `KeywordListEditor` 一致）：屏蔽词在配置页就是**一个多行文本框**，
  显示的值就是文件里的值、就是核心读到的值；保存时**只写用户输入的那一串**，
  不做拆条、不做 trim/join、不丢空项。
- **旧值**：读侧继续宽容（`\\`→`\`），所以旧版本写出的双反斜杠值在文本框里显示的就是核心实际使用的值，
  保存一次即恢复成单反斜杠。

### 修复：开机自启后服务没起来、界面显示「启动失败」

- **症状**：设置了开机自启，登录后服务没有起来，界面显示「启动失败」；之后双击图标也只会唤出那个隐藏的坏实例。
- **原因**：监听端口（默认 9321）落在系统的「动态端口范围」内时，Windows 会在登录瞬间把该端口临时分配给
  其它程序的外联连接。这时端口无法绑定，但并没有任何程序在监听。旧版本把这种情况误判成
  「端口已有其他实例在运行」并直接判失败；失败后应用又因为「端口仍被占用」拒绝退出，
  于是变成隐藏窗口，服务也一直起不来。
- **修复**：启动前先区分「真的有人在监听」和「端口被系统临时借用」；后者会在 20 秒内等待占用释放，释放后照常启动。
  真的是别的实例占用时立即提示，并在失败原因里带上健康检查详情，便于定位。
  另外，本实例从未运行过服务时，端口冲突不再阻止应用退出；自启失败会发一条系统通知而不是只写日志。

### 修复：保存配置后服务重启失败 / 关闭应用后打不开

- **症状**：核心侧（Web 管理界面）给屏蔽词写入带反斜杠的正则后，桌面端保存配置、重启服务失败；再关掉应用就再也打不开。
- **原因**：桌面端把 `.env` 双引号值当成 JSON 字符串解析（转义白名单只有 `\n \r \t \\ \"`），遇到核心写出的
  `\d` 这类就报「未知转义序列」——而这一行值同时被服务启动和启动时的管理员会话读取，于是两个症状一起出现。
- **修复**：桌面端的 `.env` 读写规则改为与随包宿主、以及与移动端 `DotEnvCodec` 完全一致——
  双引号内只还原 `\\`、`\"`、`\n`、`\r`、`\t`，其它反斜杠序列（`\d`、`\w`、Windows 路径里的 `\U` 等）
  原样保留；**任何情况下都不再因为未知转义让应用起不来**。
  写侧只在必要时加引号，且反斜杠只在后面跟着会被读成转义的字符时才转义一层，
  所以从配置页输入的正则/路径在文件里与输入逐字相同，反复保存也不会每次多加一层反斜杠。
  同时，`.env` 或会话文件损坏、被占用、不是 UTF-8 时，只影响管理员相关功能并记录明确原因，应用本身能正常启动。
- **说明**：0.4.5–0.4.7 测试包期间被写坏成双反斜杠（`\\d`）的值，在配置页再保存一次就会恢复成单反斜杠（`\d`）。
  值的写法见「常见问题 → 手动编辑 `config\.env` 时，值里的反斜杠怎么写？」。

## v0.3.8 — 全部页面外观统一（测试版）

这一版把剩下所有页面都迁到同一套外观词汇上，并修掉了几个具体问题。不改任何协议行为：

### 哪些页面变了

依次是：工具页（含它下面整棵子树）、设置页、核心页、日志页、活动页、概览页。

具体收获：

- **长列表不再一行一个描边小框**。请求记录、弹幕评论、收藏、设备列表都改成

- **按钮有了统一的主次**。「主要 / 次要 / 文字按钮 / 破坏性操作」四档全应用一致，
  之前同一个「删除」在不同页面长得不一样。
- **状态标签统一成圆角胶囊**。核心页原来那套小圆角状态片并入了全应用统一的状态标签。
- **同排卡片等高**。搜索结果与海报卡片原来是「标题一行或两行、有没有历史记录」
  决定高度，同一排参差不齐；现在四行信息固定行高。
- **顺带修掉两个真实的显示缺陷**：
  - 浅色主题下日志页深色终端里那句空状态提示对比度只有约 3.2:1（近黑底配深灰字），
    基本看不清；改用为深色面配的文字色后约 13:1。
  - 敏感变量编辑框里「显示/隐藏」的眼睛图标此前渲染成一个认不出的实心点
    （轮廓与瞳孔被拆成两个图形各自缩放，瞳孔被放大糊住了轮廓），现已修好。

### 图标

- 概览页「启动 / 停止 / 重启服务」三个按钮的图标原来是把文字字符（`▷` `□` `↻`）
  直接塞进按钮文字里——大小跟着字号走、无法单独调色、间距靠空格、换字体就换形状。
  现已改成矢量图形。同一页的「快捷操作」下拉箭头也一并换了。

### 输入框

- **所有搜索框和输入框支持回车提交**：手动匹配、弹幕下载、自动匹配、番剧详情定位、
  管理员密码、WebDAV 配置、接口调试参数，敲完直接回车即可，不用再去找按钮。
- 敏感变量的「显示 / 隐藏」改成输入框内的眼睛图标，不再单独占一个按钮。

### 界面结构上的整理（不影响观感）

- 核心页与日志页各自有一套只服务自己页面的样式，之前却定义在全应用样式文件里。
  现已搬回各自页面，全应用样式文件只保留真正共用的部分。
  这类「页面私有词汇混进公共词汇表」是同一套外观出现两个来源的根源，
  也是这一轮排查视觉问题的重点。
