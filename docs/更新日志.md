## v0.5.20（测试包，未发布）— 四源增强直连（ECH / HTTP3）

### 新增

- 设置新增「增强直连」，分为监控、配置、诊断三个页签；支持选择巴哈姆特、TMDB、弹弹play、Animeko，以及自动 / HTTP2 / HTTP3 模式和 DoH。
- 复用移动端自有 Go 网络引擎，覆盖 Node 主线程与 Worker 的核心请求；helper 随生产运行环境提供，首次准备无需安装 Go 或联网下载组件。
- 按实际域名分别显示协商协议、ECH 接受状态、HTTP 状态、耗时和错误原因；引擎就绪与源站请求通过分开判断。
- 配置原子保存并回读验证，helper 缺失、崩溃、协议错误和强制 H3 失败明确上报；停止服务与 Node 异常退出时回收辅助进程。

### 说明

- ECH 按域名策略启用，TMDB 等节点当前不使用 ECH；自动模式使用 H2 不代表 H3 验证通过。
- 本机真实测试已取得十个目标域名的 H2 完整响应，四个要求 ECH 的域名确认接受 ECH；强制 H3 在当前网络下得到 QUIC 无响应，保留失败结果，尚不能宣称公网 H3 已通过。
- 已有核心代理和备用节点会影响业务路径；独立诊断不把备用成功当成原域名直连成功。

## v0.5.19（测试包，未发布）— 本地 PR 组合恢复"检查远端更新"，并在更新前核对你并进来的 PR

### 修复

- **并了 PR 之后，更新检查不再假装"已是最新"**。以前只要当前核心是"本地 PR 组合"，
  更新检查就会被强制判成没有更新，界面上永远显示"当前已是最新提交"——等于并了 PR 就再也
  收不到上游更新。现在组合照常检查远端，有更新就显示「发现 <sha>」，侧栏也会出现更新提示。

### 新增

- **更新前先核对"远端到底包不包含你并进来的 PR"**。点更新时会逐个 PR 去 GitHub 核对：
  - 用 PR 的**合并提交**（压缩合并也只有它在主干里）和本地记录的 head 提交分别与远端最新提交比祖先关系；
  - 结论只有三种：**已包含**（附上比对了哪个提交作为证据）、**不包含**（说明是还没合并、
    还是合并提交已经不在远端历史里）、**无法确认**（GitHub 读不到，绝不瞎猜）。
- **核对结果由你决定怎么更新**：弹窗里逐个列出结论与证据，给三个选择——
  「更新并重新并入 N 个 PR」（基线换成远端最新，再把远端没有的、仍然可合并的 PR 按当前 head 并回来）、
  「仅更新（丢掉这些改动）」、「取消」。
- **PR 实验室顶部**在"组合 + 远端有新提交"时显示一行提示，说明更新会先逐个核对，
  远端没有的会按当前 head 重新并入。

### 说明

- **自动更新不会碰本地 PR 组合**：后台自动更新遇到组合只通知、不替换；托盘那一项改成
  「核对 PR 后更新（打开核心页）」，点它只打开控制台，不会绕过核对。
- 远端已经包含全部 PR 时，更新后会失去「本地并入」的标记（改动都在远端里），组合身份随之结束；
  仍然缺失的 PR 会留在新的组合里继续标记。
- 已经合并到别处、或已经关闭的 PR 无法自动重新并入，弹窗里会单独说明原因。

## v0.5.17（测试包，未发布）— 修复：点「随服务启停」闪退、以及通道状态报错/误报成功

### 修复

- **点「随服务启停」开关应用会闪退**。根因：若穿透已在运行（例如你先手动开了穿透，再来打开这个开关），
  程序仍会去"再启动一次"，被状态机拒绝后异常一路抛到界面线程，直接把进程带走。
  现在：已在运行就什么都不做（并明确回一句"已在运行"）；服务层的启停操作**永不抛异常**，
  一律转成失败结果；界面命令再加一层保护，应用级还拦截界面线程的未处理异常并记入日志
  ——是"某个操作出错"，不再是"应用消失"。
- **穿透反复报 `frpc.exe 已退出 … 7400 bind 失败`，而且中途还误报过一次"已启动"**。两个原因：
  ① 启动前的状态端口占用检查靠"试绑一下"，而 Windows 上**非独占绑定可以和已经在监听的进程共存**，
  于是有进程占着 7400 也被判成空闲；② 应用上次异常退出留下的 frpc 还在跑，状态查询问到的其实是它，
  所以先报成功、随后新进程因端口被占而退出。
  现在：端口占用判定**先查系统监听表再试绑定**；启动前先清理**本应用自己**遗留的 frp 进程
  （只认可执行文件路径与配置文件路径都对得上的，你手工启动的 frp 一律不动）；并且在下结论前
  再确认一次自己的子进程还活着。

### 说明

- 如果你机器上现在还有一个"孤儿 frpc"占着 7400，不必手工处理：装上新版后第一次启动穿透时会自动清掉；
  也可以直接结束那个进程。
- 打开开关时若穿透已在运行，不再重启它（这是正常操作顺序，不该报错）。

- **配置支持 JSON 导入导出**：导出的就是 **frp 原生 JSON**——既能贴回本应用，

- 仍然**没有连过真实公网 frps**：所有端到端验证都在本机回环拓扑上完成。

## v0.5.15（测试包，未发布）— 内网穿透：把本机服务映射到公网（frp）

### 新增

- **工具页新增「内网穿透」**：用 frp 把本机弹幕 API 暴露到公网。两种模式都支持：
  - **客户端（frpc，默认）**：填你的 frps 地址、端口与 Token，可选 TCP 端口或 HTTP/HTTPS 域名代理，
    支持传输加密、压缩、TLS；本地端口一键填成当前弹幕服务端口。
  - **服务端（frps）**：本机自己当穿透服务器（需要公网 IP 或端口映射），可配穿透端口、
    HTTP 域名端口与泛域名。
- **概览页显示穿透状态与地址**：状态（未启动 / 正在连接 / 穿透正常 / 连接中断重连中 / 失败）
  与公网地址（可一键复制）就在「连接地址」卡里；**穿透在跑但弹幕服务没跑时会明确提醒**——
  这是最容易"看着正常其实访问不了"的组合。
- **frp 由应用按需安装**：从 GitHub 官方仓库下载官方包，比对**官方 SHA256 校验和**，
  解压后再用 PE 头复核架构，最后落到 `%LOCALAPPDATA%\DanmuApi\frp\bin\<版本>\`；
  已安装时不会重复下载。

### 说明

- 穿透"通没通"以 **frp 自己的管理接口**为准（只监听 127.0.0.1）：代理 `running` 才算通，
  公网地址取 frp 返回的 `remote_addr`，失败时原样显示 frp 给的原因（例如 `port already used`）。
  进程活着但连不上服务器不会被当成"正常"。
- 配置文件（`frpc.toml` / `frps.toml`）由界面生成并整份重写，位置在 `frp\config\`；
  界面里能改的就是全部可改项。
- **Token 与本地管理密码加密保存**（Windows DPAPI），不写进 `settings.properties`、
  不进日志、界面不回显原文。
- 可以勾选「随应用启动自动拉起穿透」；退出应用会一并结束 frpc/frps，不留后台进程。
- **32 位（x86）Windows 不支持本功能**：frp 上游自 v0.52.0 起不再发布 32 位 Windows 版本，
  最后一个 32 位版本（v0.51.3）只支持已被移除的 INI 配置格式。页面会直接说明这一点，
  不会静默装一个旧版本糊弄过去。

## v0.5.14（测试包，未发布）— 配置了 GitHub Token 后全部 GitHub API 请求都改用它；安装时可直接请运行中的程序退出

### 修复

- **存了 Token、检查更新却仍报超限额**。根因：GitHub 的**匿名额度（60 次/小时，按 IP）**
  与 **Token 额度（5000 次/小时）是两个独立配额桶**，而软件的「检查更新」与核心 zipball
  下载都走 `api.github.com`、同样占这份配额。此前这两条路径**从不带凭据**，所以你保存的
  Token 只让核心检查的额度刷新了，软件更新检查仍在用已经耗尽的匿名额度，于是继续报超限——
  看起来像"缓存没刷"或"Token 没生效"，实际是两套额度各算各的。
  现在已配置 Token 时，**所有 `api.github.com` 请求都会带上它**：
  - 软件更新检查（发行版列表、签名清单与签名）；
  - 核心 zipball 下载（安装 / 更新 / 切换分支 / 重装）；
  - 核心更新检查与 PR 实验室的 GitHub API 读取（原本就已带）。
- **超限提示改成能看懂的说法**：明确说明这是"每小时 60 次的匿名额度用尽、与 Token 额度相互独立"，
  并提示可稍后重试、或在「设置 → 网络与 GitHub」配置 Token 后立即重试。

### 新增

- **安装时可以直接请运行中的程序退出**。以前正在运行时安装器只会拒绝：「弹幕 API 仍在运行，
  请从托盘完全退出后重新安装」，用户必须自己去托盘点退出再重来。现在安装器检测到程序在运行会
  **先询问**：
  - 点「是」→ 它自己安全停止服务并退出（最多等 60 秒），然后继续安装；
  - 点「否」→ 取消安装，保留原来的"自己退出后再装"的选择。
  - 请求由程序自己走本机回环通道完成（安装器不直接操作进程），**判据是单实例锁真正释放**，
    而不是"请求发出去了"——所以绝不会在程序还活着时覆盖它自己的文件。
  - 若在运行的是 **0.5.13 或更早版本**（它们不认识这条请求），安装器会如实说明该版本不支持
    自动退出、请手动从托盘退出，而不是假装成功或强杀进程。

### 说明

- **凭据只去 `api.github.com`**：第三方代理线路（gh-proxy 等）、测速探针
  （`raw.githubusercontent.com`）、发行资产 CDN 与 `github.com` 下载地址一律不带 Token，
  避免把凭据交给第三方、也避免在不需要认证的地方泄漏。
- 跨主机重定向不会带走 Token（已实测：重定向时 .NET 会剥掉 `Authorization`，
  同主机重定向同样剥离），因此 zipball 302 跳到 `codeload.github.com` 也是安全的。
- 用户把 Token 连前缀整串粘贴（`Bearer xxx` / `token xxx`）会被自动规整。
- **未配置 Token 时行为与以前完全一致**（继续匿名访问）。
- 放行规则收敛到唯一实现（`GithubTokenPolicy`），核心检查、软件更新、核心下载三处共用，
  避免以后再出现"某条路径忘了带凭据"这类分叉。

- **核心装好不再被误判为安装失败**：替换成功后若只是旧版本历史归档/临时文件清理失败，现在会作为
  提示记录，不再让整个安装报错、也不再触发应用内更新的无限重试。
- **深目录可用**：声明了长路径支持，安装或运行目录被重定向到很深的位置（OneDrive、中文长目录）
  时，解压依赖不再报"路径太长"。
- **32 位 / ARM64 发布包可自检**：发行校验不再只认 64 位的清单文件名，三种架构的签名清单
  都能各自验证。
- **下载任务的限流旁路更干净**：旁路前如果这一项根本没配置，结束后会删除而不是写一行空值；
  写完会等核心热重载落地再开跑，避免头几个请求被旧限流打回。

### 说明

- `.env` 的写入规则与核心桌面读取链路逐项核对过（含被单引号包裹的值，如 `'$1'`），
  回读校验也改成按核心的读法复核，不再只信应用自己的解析器。
- 上传、防火墙、外部命令等新行为都补了自动化用例；**真机仍需你确认一次**：装好后到工具页
  「本地弹幕」做一次文件夹导入 + 单文件上传，核对成功计数与核心里的中文文件名。

## v0.5.7 — 三架构发布（64 位 / 32 位 / ARM64）+ 修复"删核心后重装卡住"

### 新增

- **同时支持 64 位、32 位与 ARM64 三个架构**：每个架构都有安装包与免安装包，三者的界面与功能完全一致
  （内置同一套 Node.js 运行时 22.23.2，只是按架构取对应的官方二进制）。
  - **64 位**：Windows 10/11 x64；在 ARM64 的 Windows 11 上也用这一套（走系统兼容模式）。
  - **32 位**：仅用于 32 位 Windows（在 64 位系统上装不上，请用 64 位包）。
  - **ARM64**：ARM64 版 Windows 11 的原生包。
- **应用内更新只下载当前架构的包**：更新时会按你的程序架构选择对应的签名清单并校验清单里的架构字段，
  因此不会拿到别的架构的包；已装 64 位版就继续更新 64 位，ARM64 原生版就更新 ARM64。

### 修复

- **删除核心后再装回核心，服务不再卡住**。删除当前核心时应用会有意停止服务并让运行时进入
  "等待准备核心"（避免服务带着缺失的核心运行）。但在这个状态下"启动服务"按钮与托盘的同名菜单项
  都是灰的，而装回核心后又没有重新评估这个状态——结果就是核心页显示就绪、依赖也正常，
  服务却一直停在"等待准备核心"，怎么点都没反应，只能重启应用。
  现在：该状态下两处启动入口都可用（核心已装好就正常启动；核心仍缺失则照旧弹出去核心页安装的确认），
  并且核心安装/回滚成功后会重新评估该状态——核心就绪时运行时回到"已停止"，直接就能启动服务。
- **删除核心的确认按钮改为"停止服务并删除核心"**：把"会停服务"这个后果放到你实际点击的位置
  （正文原本已写明，现在更醒目）。

### 说明

- 该卡住缺陷在更早版本就存在，与内置 Node 运行时无关；触发路径是"**服务运行中删除核心 → 再装回核心**"。
- ARM64 包**尚未在 ARM64 实机上验收**（构建机是 x64，无法执行 ARM64 程序）；已用验签、PE 架构与
  SHA256 逐项核对产物，实机验证随后进行。

## v0.5.6 — 内置运行环境统一到 Node.js 22.23.2

本版把随包的内置 Node.js 运行时统一到 **22.23.2**，为后续用同一套运行时覆盖
64 位 / 32 位 / ARM64 三个架构做准备。

## v0.5.5 — 变量顺序与分类顺序对齐核心前端

以前配置页里每个分类下的变量是**按变量名字母序**排的，而核心自带前端是按它自己的读取顺序排的，

## v0.5.0 — 本地弹幕支持编辑 + 开机自启 / 启动失败修复

本版汇总四部分改动（`0.4.5`–`0.4.11` 是未发布的内部测试包，本版是这批改动的正式发行版）：

### 改动：屏蔽词改为整段文本编辑（不再拆成一条一条）

- **之前的问题**：屏蔽词编辑器把值拆成「一条一行」的列表，而正则里的 `{2,4}`、`[a,b]` 都带逗号，
  于是出现两种毛病——早期版本直接把一条正则切成 `/.{20`、`}/` 这种碎片；
  改成按核心规则分词后不再切碎，但界面仍然把一整段文本呈现成 N 个独立条目，
  既看不出原文（逗号、间距、顺序），保存时还会重新 trim/拼接一遍。
- **现在的做法**（与移动端 `KeywordListEditor` 一致）：屏蔽词在配置页就是**一个多行文本框**，
  显示的值就是文件里的值、就是核心读到的值；保存时**只写用户输入的那一串**，
  不做拆条、不做 trim/join、不丢空项。
- **旧值**：读侧继续宽容（`\\`→`\`），所以旧版本写出的双反斜杠值在文本框里显示的就是核心实际使用的值，
  保存一次即恢复成单反斜杠。

### 修复：开机自启后服务没起来、界面显示「启动失败」

- **症状**：设置了开机自启，登录后服务没有起来，界面显示「启动失败」；之后双击图标也只会唤出那个隐藏的坏实例。
- **原因**：监听端口（默认 9321）落在系统的「动态端口范围」内时，Windows 会在登录瞬间把该端口临时分配给
  其它程序的外联连接。这时端口无法绑定，但并没有任何程序在监听。旧版本把这种情况误判成
  「端口已有其他实例在运行」并直接判失败；失败后应用又因为「端口仍被占用」拒绝退出，
  于是变成隐藏窗口，服务也一直起不来。
- **修复**：启动前先区分「真的有人在监听」和「端口被系统临时借用」；后者会在 20 秒内等待占用释放，释放后照常启动。
  真的是别的实例占用时立即提示，并在失败原因里带上健康检查详情，便于定位。
  另外，本实例从未运行过服务时，端口冲突不再阻止应用退出；自启失败会发一条系统通知而不是只写日志。

### 修复：保存配置后服务重启失败 / 关闭应用后打不开

- **症状**：核心侧（Web 管理界面）给屏蔽词写入带反斜杠的正则后，桌面端保存配置、重启服务失败；再关掉应用就再也打不开。
- **原因**：桌面端把 `.env` 双引号值当成 JSON 字符串解析（转义白名单只有 `\n \r \t \\ \"`），遇到核心写出的
  `\d` 这类就报「未知转义序列」——而这一行值同时被服务启动和启动时的管理员会话读取，于是两个症状一起出现。
- **修复**：桌面端的 `.env` 读写规则改为与随包宿主、以及与移动端 `DotEnvCodec` 完全一致——
  双引号内只还原 `\\`、`\"`、`\n`、`\r`、`\t`，其它反斜杠序列（`\d`、`\w`、Windows 路径里的 `\U` 等）
  原样保留；**任何情况下都不再因为未知转义让应用起不来**。
  写侧只在必要时加引号，且反斜杠只在后面跟着会被读成转义的字符时才转义一层，
  所以从配置页输入的正则/路径在文件里与输入逐字相同，反复保存也不会每次多加一层反斜杠。
  同时，`.env` 或会话文件损坏、被占用、不是 UTF-8 时，只影响管理员相关功能并记录明确原因，应用本身能正常启动。
- **说明**：0.4.5–0.4.7 测试包期间被写坏成双反斜杠（`\\d`）的值，在配置页再保存一次就会恢复成单反斜杠（`\d`）。
  值的写法见「常见问题 → 手动编辑 `config\.env` 时，值里的反斜杠怎么写？」。

- 日志查看、API 接口调试、弹幕下载与导出、缓存管理、请求记录。
- 数据备份与恢复，支持导出到本地或同步到 WebDAV。
- GitHub 线路测速与切换，可配置 GitHub Token 提高接口配额。

### 软件更新

- 内置带签名的软件更新通道，可在应用内检查、下载并更新本应用。
- 支持关闭自动检查、跳过指定版本。

### 已知限制

- 仅提供 **Windows x64**，要求 Windows 10 19041（20H1）及以上；暂不支持 32 位与 ARM64。
- 使用项目自签名证书，安装时可能提示"未知发布者"/SmartScreen 警告。
- 界面目前只有简体中文。
- 首次启动需要准备运行环境（约 10–30 秒，视磁盘与杀毒软件而定），仅需一次。
- 自定义核心与 PR 实验版本未经稳定版校验，建议用「本地版本历史」随时回退。
