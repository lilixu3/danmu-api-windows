# 安装与使用

面向使用者的操作说明。遇到具体报错先看 [常见问题](常见问题.md)。

## 1. 安装

两种形态功能完全相同，选一个即可：

- **安装版** `DanmuApi-<版本>-win-x64-setup.exe`
  写入开始菜单、注册卸载项，可勾选开机自启；推荐日常使用。
- **免安装版** `DanmuApi-<版本>-win-x64-portable.zip`
  解压到任意目录（建议非中文、非受保护目录，例如 `D:\DanmuApi`），双击 `DanmuApi.App.exe`。

包内已含 .NET 运行时、Node.js 与全部生产依赖，**不需要**另外安装 .NET、Node 或 npm。

> 首次运行若出现"Windows 已保护你的电脑"：点 **更多信息** → **仍要运行**。
> 原因与校验方式见 [README 的对应章节](../README.md#关于windows-已保护你的电脑)。

## 2. 首次启动

首次启动会在后台"准备运行环境"，把随包的 Node 与生产依赖铺到
`%LOCALAPPDATA%\DanmuApi\runtime\`。这一步在概览页有进度提示：

- 通常 10–30 秒，磁盘慢或杀毒软件实时扫描时会久一些；
- 只需一次，之后启动是几十毫秒级的快速校验；
- 准备期间可以浏览其它页面，但不能启动服务。

如果准备失败，页面会给出失败原因与修复入口，按提示重试即可。

## 3. 安装弹幕核心

应用**不内置核心**，第一次使用需要装一份 —— 也就是上游项目
[`huangxd-/danmu_api`](https://github.com/huangxd-/danmu_api)：

1. 左侧进入「核心」页；
2. 「管理对象」选择 **稳定核心**（上游 `huangxd-/danmu_api`，推荐）或 **自定义核心**；
3. 点 **安装稳定核心**（自定义核心则填仓库地址，可带分支，用于跑自己的分支或别人的魔改版）；
4. 首次会要求测速并选择一条 GitHub 线路——列出的都是加速镜像，选延迟低、速度高的即可，
   选完会被记住，后续默认复用；
5. 等待下载安装完成，工作台会显示版本、分支、提交与安装时间。

装完以后，这个核心就已经在本机就位了：它的代码、配置和依赖都在
`%LOCALAPPDATA%\DanmuApi\runtime\nodejs-project\` 下，由本应用负责启动和看护。

「核心」页还能做这些事：

| 操作 | 说明 |
|---|---|
| 检查更新 / 应用更新 | 检查到新提交后会问你是否立即更新，也可以稍后再应用 |
| 本地版本历史 | 保留最近几个版本，可一键回退，不需要重新下载 |
| 提交历史 | 浏览当前分支的提交，可查看变更或回退到指定提交 |
| PR 实验室 | 把某个 PR 装成自定义核心，用于尝鲜未合并的改动 |
| 切换分支 | 选目标分支后点「切换」，会重装成该分支最新提交 |
| 重新安装 | 按当前来源重新拉取一遍，配置与日志不受影响 |
| 修改名称 / 删除核心 | 只影响本机展示或核心目录，不会动你的配置 |

> 自定义核心与 PR 实验版本未经稳定版校验，出问题可以用「本地版本历史」回退。

## 4. 配置服务

「配置」页的变量清单来自**当前核心自带的 `configs/envs.js`**，所以换核心后清单会自动跟着变。

- 左侧可按分类、类型、配置状态筛选，也可以直接搜索变量名；
- 右侧（窄窗口下是弹窗）是变量详情与编辑器，不同类型对应不同控件；
- 每个变量都会标出**当前值的来源**：进程环境 / `.env` 显式配置 / 核心默认；
- Token、Cookie、API Key 一类敏感值默认打码，需要时点「显示敏感值」；
- 保存写入 `config\.env`，核心**热重载**，不用重启服务；
- 「恢复默认」会删掉 `.env` 里的显式值，让核心回到默认。

几个常用变量：

| 变量 | 作用 |
|---|---|
| `DANMU_API_PORT` | 服务端口，默认 `9321` |
| `DANMU_API_HOST` | 监听地址。`0.0.0.0` 允许局域网访问，`127.0.0.1` 仅本机 |
| `TOKEN` | 接口访问路径里的口令，默认 `87654321`，**建议改成自己的** |
| `PROXY_URL` | 反代或代理地址，按需设置 |
| `LOCAL_REDIS_URL` | 配了才会启用 Redis 缓存，见 [常见问题](常见问题.md#可选-redis-要配吗) |

端口与 Token 也可以在「设置」里改（那里会同时处理接口地址的展示）。

## 5. 启动与访问

1.「概览」页点 **启动服务**；
2. 状态变为「服务运行中」，页面上会显示访问地址与端口；
3. 首次启动如果弹出 **Windows 防火墙** 授权，请允许（否则局域网设备连不上）；
4. 把地址填进播放器 / 客户端：
   `http://<本机IP>:9321/<TOKEN>`，本机可用 `http://127.0.0.1:9321/<TOKEN>`。

概览页还能看到今日请求统计、最近请求等，用来确认服务是不是真的在被使用。

### 关于防火墙

- 只在**第一次**启动服务时需要授权，之后不再提示。
- 若当时拒绝或误点了取消，可以在「设置」里重新申请，或手动到
  「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」中放行。
- 只想本机使用的话，把监听地址改成 `127.0.0.1` 就不需要放行。

## 6. 桌面集成

在「设置」里可以配置：

| 设置 | 说明 |
|---|---|
| 主题 | 浅色 / 深色 / 跟随系统，实时切换 |
| 开机自启 | 登录后后台启动（不弹窗口，驻留托盘），适合当常驻服务 |
| 关闭窗口时 | 询问 / 退出应用 / 最小化到托盘 |
| 通知 | 关闭 / 仅更新与依赖提醒 / 仅自启成功 / 全部 |
| GitHub Token | 配置后接口配额更高、下载更稳（保存在 Windows 凭据加密存储中） |
| GitHub 线路 | 测速并选择加速线路，可随时切换 |
| 数据与备份 | 备份 / 恢复核心配置与数据，支持 WebDAV 远端 |

托盘图标右键可以启动/停止服务、打开主界面、打开配置目录、退出。

## 7. 软件更新

- 应用默认在启动 30 秒后检查一次，之后每 6 小时检查一次；也可在「关于」页手动检查。
- 发现新版本后侧栏会出现提示，可在应用内下载并更新，更新过程会先停服务、完成后再拉起。
- 可以关闭自动检查，或跳过某个版本（跳过只影响自动提示，手动检查仍能看到）。

核心更新与软件更新是**两回事**：「核心」页更新的弹幕核心，「关于」页更新的是本应用。

## 8. 卸载与数据

- 卸载程序**不会删除**你的核心、配置和日志，卸载后重新安装可直接接着用。
- 想彻底清理，删除 `%LOCALAPPDATA%\DanmuApi` 与 `%APPDATA%\DanmuApi` 两个目录即可。
- 卸载前建议在「设置 → 数据与备份」里导出一份备份。
