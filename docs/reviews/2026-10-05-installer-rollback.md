# 安装器回退记录

日期：2026-10-05。候选版本：0.5.24。状态：源码已修改；未构建签名发行包、未安装覆盖、未发布。

## 问题与变更

旧版应用内更新助手以 `UseShellExecute=true, Verb=runas` 启动安装器。v0.5.23 新增的原用户中继拒绝管理员令牌；同版本修复又引入普通用户令牌和安装锁租约，仍拒绝没有关联普通用户令牌的管理员环境。此次按用户要求采用回退方案。

`installer/DanmuApi.iss` 完整恢复为正式 tag `v0.5.13`（提交 `856904275e54cb64d4d03dc9e67103c714db20f6`）中的原始字节。新版应用代码、签名公钥、安装 AppId、架构规则和发行构建脚本不变。当前更新助手继续使用现有启动方式和错误诊断，旧更新助手的 `runas` 入口由原安装协议接收。

恢复的安装协议：

1. 检查 `/UPDATEREADY` 路径和原应用 PID。
2. 打开原应用进程句柄，写入 `installer.ready`，等待原应用退出，检查取消标记。
3. 检查 `{userappdata}\DanmuApi\instance.lock` 与旧 `app.lock`；锁被占用时停止安装。
4. 执行原有旧 MSI 迁移、文件安装及自启处理。

安装器不再提取或执行 `DanmuApi.ExitRelay.exe`，也不再调用 `--installer-update-lease`。应用中保留的中继辅助代码不参与本次安装路径。删除仅用于断言这段已撤回 Pascal 源码的五项静态测试；保留更新助手启动参数、架构注册表视图、更新诊断、实例退出协议和中继辅助方法本身的测试。

`Directory.Build.props` 的产品、程序集和文件版本统一提高为 0.5.24。发行构建脚本从该文件读取版本并生成包名和签名更新清单，因此旧客户端无需改变更新协议即可发现更高版本。

## 验证与边界

本地核对安装器与 `v0.5.13:installer/DanmuApi.iss` 字节完全一致；检查版本来源、现有更新参数与旧协议兼容，以及发行脚本沿用既有签名和打包路径。`git diff --check` 用于检查补丁格式。

本次执行环境为 Android/Termux，没有 Windows、.NET SDK 或 Inno Setup。未运行 .NET 回归、Inno 编译、UAC 或真实安装升级，不能将源码回退等同于实机验收成功。

回退也恢复旧版的限制：实例锁路径来自 Setup 的 `{userappdata}`，并且检查后不持续持锁；不同账户授权 UAC 时的用户目录、自启项归属，以及退出后另一个实例重启的竞争，仍须在 Windows 上验证。

发布前至少完成：

- 构建并签名 x64、x86、ARM64 的 0.5.24 包及各架构更新清单，保持既有证书身份；检查包内应用实际版本、包名和签名清单一致。
- 在合适架构的 Windows 上，用未经修改的正式 v0.5.13、原 v0.5.23 和同版本修复后的 v0.5.23，分别通过应用内下载升级至候选，不用新助手模拟旧入口。
- 覆盖普通用户、自提权应用/无关联普通用户令牌的管理员环境、UAC 取消，以及不同账户授权；核对退出、覆盖、重启、核心/配置保留及自启归属。
- 手动运行安装器时，已有实例仍运行应被阻止；应用内升级必须等待原 PID 退出后才开始复制。

公开发行会让旧客户端检测到 0.5.24 并使用回退后的安装流程。完成候选包和实机验收后，再确认公开发布。
